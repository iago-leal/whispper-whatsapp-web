Plano de Correção

Bug #1 · BUG-20261001-MAC1 · contexto compatibilidade-instalacao · 2026-10-01 · critical P0

Defeito e causa raiz

Defeito: o instalador baixado pela página de boas-vindas não abre no macOS: o Gatekeeper o bloqueia e, forçada a abertura, o Instalador falha com com.apple.installer.pagecontroller erro -1.

Causa raiz confirmed: configurarDownload grava no botão href="#download-whispper-macos-apple-silicon.pkg" com o atributo download. Um link para fragmento da própria página faz o Chrome salvar o documento atual com o nome pedido; o "pacote" é o HTML de onboarding/index.html. Nenhum artefato do repositório gera um .pkg real servido pela extensão.

Evidências (cápsula de reprodução):

  • Os quatro .pkg em ~/Downloads têm o SHA-256 de extension/onboarding/index.html (69248b35…); file os identifica como HTML (pkg-baixado-e-html.txt).
  • O gerador não versionado da sessão anterior instala com "sucesso" aparente, mas o postinstall falha ao ler ~/extension/manifest.json e o host nunca é registrado (install-log-20261001-1053.txt).
  • Protótipo sem payload, domínio só do usuário: instala sem sudo, com o postinstall rodando como uid 501 e os arquivos embarcados disponíveis.

Estratégia escolhida

Correção direta, com o instalador embutido na extensão (decisão do usuário em 2026-10-01). O debate anterior já tinha fixado o pkgbuild num domínio só do usuário; a parte que apontava o link para o GitHub caiu com o BUG-20261001-404B, e os três defeitos do gerador antigo vieram de evidência nova.

  1. Pacote sem payload: o motor (motor.sh + whispper_motor/*.py) e o extension/manifest.json vão na pasta de scripts, no mesmo layout do repositório, para que instalacao.py encontre a key em parents[2]/extension/manifest.json.
  2. postinstall herda o PATH do shell de login do usuário (onde estão o Python com mlx-whisper e o ffmpeg), grava log em ~/Library/Logs/whispper-motor-instalacao.log e devolve o código real de saída do motor.sh instalar.
  3. O .pkg é gerado em extension/dist/instaladores/ e o botão aponta para chrome.runtime.getURL('dist/instaladores/<arquivo>') com download.

Riscos

change_risk média

  • Artefato novo de distribuição e comportamento do Instalador do macOS em domínio de usuário.
  • Altera o link da página de boas-vindas, o mesmo ponto do 404B.
  • Reversível: sem dados persistidos nem contrato externo; a instalação só grava na pasta do usuário.

Fora desta correção (Agent Notes):

  • Assinatura e notarização (RNF-03): dependem do Programa de desenvolvedor da Apple (OQ-03). O alerta do Gatekeeper continua e exige "Abrir Mesmo Assim" em Ajustes.
  • O pacote ainda depende de Python 3.11+, mlx-whisper, ffmpeg e do modelo já presentes na máquina. Para o usuário leigo, isso fica aquém do RF-07; empacotar um runtime próprio é trabalho de feature, a registrar à parte.
  • O instalador do Windows (whispper-windows-x64.exe) não existe; o link passa a falhar como download em vez de baixar HTML. O aviso de falha com nova tentativa (seção 10 da spec) fica para o ciclo do 404B.
